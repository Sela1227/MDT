# MDT 會議管理系統

**彰濱秀傳癌症中心 多專科團隊會議管理工具**
部署網址:https://sela1227.github.io/mdt-system/
單一 HTML 檔案,無後端;資料存於各台電腦的 localStorage,經院內 NAS `sync/` 資料夾同步。

> 本檔描述**系統現況**。版本歷程見 `CHANGELOG.md`;開發規則、資料架構、主任決策見 `CLAUDE.md`;個管師操作見 `USER_GUIDE.md`。
> **改到資料架構、產出規則、同步機制時,同一版就改本檔。**

## 主要功能

### 行事曆與會議清單
- 登入後顯示本月行事曆;依各癌別「第幾個星期幾」顯示預排格
- 點已有記錄進入會議;點預排格建立新會議
- 歷史記錄:年月分組,癌別 + 個管師雙篩選

### 會議內容
- **個案討論**:病歷號、遮蔽姓名、年齡/性別、主治醫師、診斷、病史、病理、檢查、治療、討論方向、摘要、決策、影像、病程時序、基因檢測
- **必要事件**:死亡個案等必要提報,含臨床資料與病程時序
- **醫療小組 / 前期追蹤 / 特殊議程**
- 個案區頂端情境列顯示「日期 | 癌別 | 個案數 | 閱覽/編輯」

### 合併開會
- 各個管師編輯自己負責的癌別分頁
- **所有文件產出(HTML 投影片、HTML 分享、Word 簡報、DOCX 記錄、會議小抄)永遠只出目前分頁的那個癌別**,沒有合併成一份的流程;要出另一個癌別就切分頁再按一次。LINE 通知例外(合併為一則)。
  —— 2026-09-24 主任定案,程式中 `getOutputCid()` 註解為設計不變量

### 影像
- **會議資料只存檔名與指紋**,影像本體留在選定的影像資料夾(依病歷號子資料夾)
- 病歷號子資料夾:匯入個案後與選取影像時自動建立(需「可修改」權限,V5.73.0);選取時**不再**退回會議資料夾本身(產出端嚴格模式本來就不載入那些影像)
- 產出投影片時讀取資料夾;可選「夾在投影片」或「另開視窗」

### 產出區

| 分組 | 按鈕 |
|---|---|
| 會前通知 | LINE 通知 |
| 開會資料 | HTML 投影片、**HTML 分享**、Word 簡報、會議小抄 |
| 決議與紀錄 | 填寫會議決議(面板可依癌別/待填篩選)、DOCX 記錄 |
| 更多工具 | Excel、JSON 匯入匯出、AI 提示詞 |

檔名:`20260618-HN_MDT.html`(日期-癌別縮寫)。

### 投影片分享
- 「HTML 分享」上傳到 Cloudflare Worker(`share.selaginella.io`),網頁只帶**上傳金鑰**
- 醫師開啟需輸入**檢視密碼**(關閉瀏覽器即失效);投影片 90 天後自動過期
- 部署與測試見 `cloudflare-share/DEPLOY.md`、`test.mjs`

### 設定
地點、醫師(依科別)、癌別(地點/時間/召集人/開會週次/色碼)、AI(API Key 不進備份)、投影片分享(上傳金鑰)、Zoom 密碼、NAS 與影像資料夾。

### 刪除保護
所有刪除需輸入隨機四碼確認。

## 資料與同步

- 資料架構(五類 localStorage key、會議物件欄位)見 **`CLAUDE.md` 第五節** —— 本檔不重複,避免兩份不一致
- **NAS 同步**:每場會議一個檔案 `sync/mdt_m_{id}.json`。每次存檔 `version+1` 並產生新的 `rev`(內容指紋)。
  - 開啟會議時先拉 NAS 較新版
  - 存檔前比對 NAS 的 `rev`:別台改過就**依癌別區段合併**(不是我負責的癌別取 NAS 版);我負責的癌別也被改過(同一人兩台)才跳衝突視窗
  - 「這台電腦最後推送成功的 rev」存在獨立 key `mdt_pushed_{id}`,不進會議物件
- **每日備份**:設定、會議、偏好與影像清單寫到 NAS;金鑰與單台狀態不進備份

## 技術規格

- 單一 `index.html`(約 13,000 行),無框架、無後端
- CDN(jsdelivr.net,按需載入):`xlsx@0.18.5`(Excel 匯入匯出)、`pptxgenjs@3.12.0`(舊 PPTX 路徑);**docx 7.8.2 與 JSZip 內嵌**(V5.35.0 起,離線可用、供應鏈安全;`loadLib` 偵測到已存在就不下載)
- 字型:Noto Sans TC + Noto Serif TC
- AI:api.anthropic.com 或 api.openai.com(設定頁選擇;送出前去識別化該個案病歷號與姓名)
- 瀏覽器:Chrome / Edge(File System Access API)

## 上線前檢查

```bash
python3 preflight.py          # 全部(約 1 分鐘)
python3 preflight.py --quick  # 只跑靜態
```
全部 ✅ 才能打包;它會印出 zip 指令。需要 node、jsdom、jshint。

**投影片內容等價測試**(V5.75.0):`content-equiv.js` 用固定的虛構會議產出 HTML 投影片,逐頁比對文字與 `content-baseline.json`。投影片上的字只要變了(多頁、少頁、標籤改名)preflight 就 🔴。**經主任同意改投影片內容後**才執行 `node content-equiv.js --update` 更新基準,並在 CHANGELOG 寫理由。

**預覽與畫重點**(V5.76.0):產出區「預覽與畫重點」以 blob 分頁開投影片;投影片的「存標記」以 `postMessage` 傳回系統,存進 `sections[cid].hlMarks`(`{marks:{頁面文字指紋:[[起始,長度,tag,style,class]]},at,by}`),隨會議存檔與 NAS 同步;產出時以 `<script id="hl-sys">` 帶進投影片,依文字指紋套用。系統有未儲存修改時拒存。檔案路徑(`hl-data`)保留給會議室直接開檔;檔案存了自己的標記後 `hl-sys` 失效。`preview-check.js`(真 Chromium)端到端檢查。

**共用測試會議**(V5.76.0):`test-meeting.js` 一份真實份量的虛構會議,`content-equiv.js`、`layout-check.js` 共用。

**投影片版面檢查**(V5.75.2):`layout-check.js` 用前期追蹤 10 位的虛構會議產出投影片,在真的 Chromium 以 1920×1080 與 1366×768 逐頁檢查「內容沒超出,或該頁可以捲」,前期追蹤表捲到底最後一列要在導覽列上方。需要 playwright;沒有時 preflight 🔴,可加 `--no-layout` 明確略過。
